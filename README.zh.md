# 纯对话（Pure chat）

中文 | [English](README.md)

一个 DSH bundle，增加一个可选的 **agent 预设**。使用该预设的会话会把对话直接发给模型——没有系统提示词，也没有文件、Shell、终端、技能、子代理、团队或目标工具——只暴露三个自有工具：

- `web_search`——联网搜索，返回可选摘要和来源；
- `web_fetch`——把指定 URL 抓取为 markdown 或纯文本；
- `write_file`——把文本保存为会话工作目录中的文档。

bundle 还在输入框发送按钮左侧增加了一个**清空上下文**按钮：它只重置模型读到的内容，不改动你看到的对话。

## 使用方法

1. 新建会话。
2. 在输入框上方的预设控件（“新建会话”那一行）选择 **Pure chat (纯对话)**。
3. 直接提问。需要最新信息时，模型会调用 `web_search`（需要读具体页面时调用 `web_fetch`），然后基于结果回答。

预设会记录在会话里，重启后仍保持该行为。会话保留启动时使用的组合：更新本 bundle 后，请新建会话以获得新行为。

## 模型能看到什么

- 你的用户消息、助手回复、联网工具调用及其结果。
- 一条 DSH 为校验会话目录而必需的运行时提示，例如 `Current working directory: "C:\..."`。
- 三个工具的 schema（名称、描述、参数）。
- 会话选择的模型路由和推理强度。

不会收到：Harness 身份、agent 指令、人格、技能目录、常规工具使用说明、沙箱/审批策略，以及任何子代理身份。所有宿主级全局工具（包括宿主作用域挂载的 Agent Teams 工具）都会被 bundle 插件隐藏；预设只挂载自己的三个工具。

## 导出文件

直接说“把上面的内容导出成 PDF”即可，模型会调用 `write_file`，传入路径、完整内容和可选的格式。支持的格式：

| 格式 | 实际写出的内容 | 可用软件打开 |
|---|---|---|
| `txt` | UTF-8 文本 | 任意编辑器 |
| `md` | UTF-8 Markdown | 任意编辑器、DSH |
| `doc` | RTF 文档（`.doc`） | Word、WPS、LibreOffice |
| `xls` | SpreadsheetML 工作簿（`.xls`） | Excel、WPS |
| `pdf` | 真正的 PDF | 任意 PDF 阅读器 |

需要注意：

- 文件写入**会话工作目录内部**；越出该目录的路径会被拒绝，缺失的父目录会自动创建。
- `xls` 每行一条记录，单元格之间用制表符分隔（整行没有制表符时用逗号）；第一行作为表头，纯数字单元格会写成数值。
- `pdf` 通过 DSH 的 Office 组件（`office-kit`）渲染同一份文档，因此中文能保留字体；没有该组件时工具会明确报错，而不是写出打不开的 PDF。
- 单次内容上限 4 MiB。由于两种格式不是 UTF-8 文本，工具直接写字节，上面的路径检查就是它的边界。

## 清空上下文

输入框发送箭头左侧有一个小按钮，只在选用本预设的会话中出现。

1. 点击按钮，会弹出确认对话框说明影响。
2. 确认后，模型从全新的上下文开始回答。

具体发生了什么：DSH 的模型历史来自会话的有序 **surface**，所以清空会追加一条合成的用户消息，用一次 surface 替换覆盖此前所有对话节点。日志保留全部事件，对话记录里每条消息都原样保留，下一次请求只派生那条新消息；聊天区只渲染追加的消息，因此也不会多出气泡。当前回合仍在生成时命令会拒绝执行，已经没有可清空的内容时会提示“已为空”。

同一操作也以 `/clear-context` 命令的形式提供给本预设。

## 工具是怎么被隐藏的

预设在自己的作用域里挂载自有工具，并按名字拒绝全部宿主全局工具（`ctx.tools.restrict({ deny })`）。作用域内的注册不受这条掩码影响，所以预设工具照常可见；不能用 `allow: []` 代替，因为注册表会拒绝空过滤器。

- 拒绝列表在**每次 `tools/change` 时重新计算**，不是激活时的一份快照。因此之后才注册的全局工具——后装的插件、HMR 重载——同样会被隐藏。
- `run_code` 永远不写进拒绝列表，因为注册表为它保留了名字；本预设也没有挂载 PTC 执行器，所以它在这里同样不可调用。
- 如果注册表拒绝了这条限制，预设会**激活失败**，而不是悄悄变成一个拥有全部工具的 agent；对应的插件行会在 Plugins 里显示诊断信息。

## 限制

- **工具调用仍属于 agent 循环的工作。** 联网查询与文件写入以模型工具调用的形式执行，由 agent 循环完成；除此之外，整个回合就是普通聊天。
- 工具说明所在的系统提示词段落被一并移除，模型只能依赖每个工具自身的简短描述。对于看起来像常识的问题，它可能不会主动搜索；如果没有搜，明确说“查一下……”即可。
- 没有挂载压缩（compaction），对话很长时会超出模型上下文；可以新建会话、清空上下文，或换用上下文更大的模型。
- 仅当所选模型路由有可用的搜索 provider 时，`web_search` 才会被允许；`web_fetch` 使用 HTTP provider，始终可用。
- `pdf` 需要 DSH 的 Office 组件；`doc` 和 `xls` 不需要额外组件。
- 预设是组合配置，不是安全边界：它控制模型被告知什么、能调用什么，不控制谁可以安装插件。

## 环境要求

- DSH `>= 0.2.2-rc.5`，以 `engines.dsh` 声明。
- `web_search` 需要配置好的搜索 provider；`web_fetch` 不需要。
- 清空上下文按钮需要 Web 客户端 bundle（`dsh-client-ui-conversation`）；PDF 导出需要 `office-kit`。

## 安装

从 GitHub 安装：

```sh
dsh plugin --profile <profile> add github:EonCosmos/dsh-pure-chat
```

本地开发时，也可以用 **Plugins → Add plugin → 本目录**，或
`plugin_manager` 的 `action: install_bundle`，`target` 填本包目录。

## 升级

Git 安装不支持一键更新，请用上面的安装命令重新安装。预设 id 仍是 `pure-chat`，已选择它的会话不受影响。

1.2.0 把包名从 `@local/dsh-pure-chat` 改成了 `dsh-pure-chat`。请先移除旧 bundle（**Plugins → 移除**）再安装，否则 profile 里会同时留下两行，同一个预设也会被声明两次。

1.3.0 增加了 `write_file` 工具和清空上下文按钮；会话保留启动时的组合，请新建会话查看新功能。
